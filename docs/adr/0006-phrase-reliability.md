# ADR-0006: 문구 교체·날짜·운영 API 경계

## Status

Accepted — 2026-09-11. 사용자가 로컬 구현·회귀 테스트 보완 결과를 승인했다.

## Context

[작업 계획](../plan/0007-phrase-reliability.md)의 문제·선택지·영향 범위를 따른다. 운영 데이터와 Cloudflare Access 설정은 아직 조회하지 않았으므로 중복이 없거나 외부 인증이 적용됐다고 가정하지 않는다.

## Decision

- 문구 교체는 D1 batch 안에서 원본을 종료하고 새 문구를 만든다. 원본의 replacement_id가 이번 요청의 새 ID와 일치할 때만 생성한다. 재시도는 기존 교체 결과의 문장이 같을 때만 성공으로 돌려준다.
- 사용자별 status='active' 행에 부분 고유 인덱스를 둔다. 기존 중복을 자동 종료·삭제하지 않고 마이그레이션을 실패시킨다.
- 현재 문구의 오늘은 서버 시각과 요청의 IANA 시간대로 계산한다. 클라이언트 시각으로 미래·과거 기록을 만들지 않는다. 잘못된 시간대는 UTC로 대체한다.
- 방문 이벤트의 UTC 시각은 현재 요청 시간대로 변환하고, 되새김 log_date는 기록 당시 달력 날짜 그대로 센다. 여행 등 시간대 변경 시 과거 방문일은 현재 시간대로 재해석된다. 별도 시간대 이력 복원은 범위 밖이다.
- 운영 퍼널·보고서는 기존 UTC 기준을 유지한다. 프론트 눈금은 24시간 밀리초 차감 대신 달력 날짜를 이동해 DST를 처리한다.
- 운영 HTTP 경로는 ADMIN_API_TOKEN Bearer 인증으로 보호하며 비밀이 없으면 기본 차단한다. 내부 cron은 HTTP 인증과 무관하다. 사용자 인증 체계는 이번 범위 밖이다.

## Consequences

신규 SQL과 Worker를 프론트엔드보다 먼저 배포해야 한다. 교체 재시도는 문구를 중복 생성하지 않지만, 분석 이벤트는 기존처럼 best-effort이며 트랜잭션에 포함하지 않는다. 오래된 클라이언트의 두 요청 교체는 새 프론트엔드 반영 전까지 남을 수 있다.

D1 batch의 실패 시 전체 롤백 계약은 [Cloudflare D1 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)를 기준으로 한다.
