# Problem 1-Pager: 프로젝트 폴더 경계 명확화

## Context

현재 제품과 레거시의 차이는 문서와 라우터에는 기록되어 있지만 실제 폴더 구조에는
반영되지 않았다. 과거 실험·계획도 현재 기준 문서와 가까운 위치에 섞여 있다.

## Problem

AI 에이전트가 파일 존재와 위치를 활성 여부의 신호로 사용하면 레거시 Worker 서비스를
현재 구현으로 오해하고, 과거 제품 실험을 현재 요구사항으로 해석할 수 있다.

## Goal

- Worker 활성 서비스와 레거시 서비스를 디렉터리 경계로 구분한다.
- 현재 기준 문서와 과거 실험·프로토타입·피벗 이전 계획을 구분한다.
- 모든 import와 문서 링크를 유효하게 유지한다.

## Non-Goals

- 레거시 코드나 역사 문서 삭제
- 프런트엔드 전체 기능 폴더 재편
- API, DB, 런타임 동작 변경

## Constraints

- 파일 내용과 Git 이력을 보존하는 이동을 우선한다.
- Worker 레거시는 라우터에서 계속 도달 불가능해야 한다.
- 이동 후 프로덕션 빌드와 Worker dry-run으로 검증한다.

## Options

1. 문서 표지만 강화한다: 코드 이동 위험은 없지만 파일 위치가 주는 잘못된 신호는 남는다.
2. 레거시와 역사 자료를 전용 폴더로 이동한다: 참조 갱신이 필요하지만 구조 자체가 상태를
   설명한다.

**Decision:** 2번을 선택한다. 프런트엔드는 현재 규모에서 이동 비용이 더 크므로 이번 범위에서
제외한다.

## Impact Note

Worker 레거시 파일의 상대 import와 문서 경로만 바뀐다. 활성 라우터는 해당 파일을 import하지
않으므로 Worker 번들과 API 동작은 동일하다.
