# Problem 1-Pager: AI 프로젝트 컨텍스트와 용어 정리

## Context

단단이는 2026-08-28 챌린지/Story Feed 제품에서 **매일 한 문장을 되새기는 제품**으로
전환했다. 현재 프런트엔드와 활성 API는 전환된 모델을 사용하지만, 최상위 README와
개발 문서에는 이전 모델이 현재 제품처럼 남아 있다.

## Problem

AI 에이전트와 새 기여자가 오래된 문서를 먼저 읽으면 `challenge`, `practice`, `story`를
현재 도메인으로 오해할 수 있다. 같은 현재 개념도 문구/문장, 기록/로그처럼 여러 말로
표현되어 검색과 변경 영향 분석이 불명확하다.

## Goal

- 현재 제품의 목적, 활성 사용자 흐름, 실행 경로를 짧은 문서에서 파악할 수 있게 한다.
- 한국어 제품 용어와 코드/API 용어의 1:1 대응을 정의한다.
- 레거시 자산을 삭제하지 않되 현재 기능과 명확히 구분한다.

## Non-Goals

- 레거시 Worker 서비스나 D1 테이블 삭제
- 공개 API, 데이터베이스 스키마, 분석 이벤트 이름 변경
- 과거 ADR과 실험 문서의 역사적 표현 일괄 수정

## Constraints

- ADR-0005의 레거시 보존 결정을 유지한다.
- 코드와 저장된 데이터에서 이미 사용 중인 영문 식별자는 호환성을 위해 유지한다.
- 현재 상태의 근거는 프런트엔드 import 경로와 Worker 라우터로 한정한다.

## Options

1. `DEVELOPMENT.md` 전면 개정: 한 문서에 통합되지만 변경 범위가 크고 운영 정보까지
   함께 낡게 만들 위험이 있다.
2. 현재 상태 전용 문서를 만들고 최상위 진입점에서 연결: 문서가 하나 늘지만 작은 변경으로
   현재와 역사를 분리할 수 있다.

**Decision:** 2번을 선택한다. `docs/PROJECT_CONTEXT.md`를 현재 상태의 기준으로 삼고,
README와 AGENTS.md에서 가장 먼저 안내한다.

## Assumptions

- `frontend/src/App.js`에서 도달 가능한 화면과 `workers/src/router.js`에 등록된 라우트를
  현재 제품의 실행 가능한 범위로 본다.
- `docs/adr/0005-legacy-backend-inventory.md`의 2026-09-06 인벤토리는 별도 변경 전까지
  레거시 판정의 기준이다.
