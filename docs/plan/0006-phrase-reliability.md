# 문장 되새기기 신뢰성 개선

## Problem 1-Pager

- **Context:** 문서 정비 후 승인된 후속 계획(첫 방문, 문구 교체, 중복 생성, 날짜, 운영 API)을 구현한다.
- **Problem:** 최초 방문이 anonymous로 기록되고, 문구 교체 중 실패하면 활성 문구를 잃는다. 동시 생성에는 DB 제약이 없고, 방문 날짜와 눈금 계산은 UTC·DST 경계에서 어긋난다. 운영 HTTP 경로에 인증 검사가 없다.
- **Goal:** 사용자 식별 일관성, 원자적·재시도 가능한 문구 교체, 사용자별 활성 문구 하나, 로컬 달력 기준 표시, 운영 API의 기본 차단을 회귀 테스트로 보장한다.
- **Non-Goals:** 로그인 도입, 기존 사용자 ID 복구, 레거시 삭제, 운영 데이터 자동 정리, 운영 배포·메시지 발송.
- **Constraints:** 기존 문서 변경을 보존한다. 외부 시스템은 테스트 대역으로 대체한다. 신규 SQL은 데이터 삭제 없이 실패하도록 한다. 운영 중복 데이터의 존재와 Cloudflare Access 설정은 로컬 저장소만으로 확인할 수 없다.

## 선택지와 결정

| 영역 | 선택지 A | 선택지 B | 결정 |
|---|---|---|---|
| 최초 사용자 | 진입점에서 ID 생성: 변경은 작으나 다른 호출은 보장하지 못함 | 분석에서도 공통 ID 유틸 사용: 모든 이벤트에 동일 규칙 적용 | B. 분석 전송 코드를 분리해 기존 긴 파일의 책임도 줄임 |
| 문구 교체 | 클라이언트 보상 요청: 단순하나 보상도 실패 가능 | D1 batch로 종료·생성: 스키마 추가가 필요하지만 함께 롤백 | B. 이전 문구에 replacement_id를 저장해 동일 요청 재시도 처리 |
| 동시 생성 | 사전 조회: 경합을 막지 못함 | 부분 고유 인덱스: DB가 최종 보장, 기존 중복 시 적용 실패 | B. 중복 점검 SQL 제공, 임의 데이터 정리 금지 |
| 날짜 | UTC 날짜/24시간 차감: 단순하나 로컬 자정·DST 오류 | 시간대 변환과 달력 날짜 연산: 정책 명시 필요 | B. 사용자 화면은 요청 시간대, 운영 집계는 UTC 유지 |
| 운영 API | Cloudflare Access에 의존: 외부 설정 확인 필요 | Worker Bearer 토큰 검증: 저장소에서 검증 가능 | B. ADMIN_API_TOKEN 미설정 시 HTTP 운영 경로 차단, cron은 내부 실행 유지 |

## 영향 범위

- 분석 이벤트는 기존 export를 유지하고 공통 사용자 ID 생성 함수를 사용한다. PostHog가 없어도 D1 전송을 유지한다.
- 문구 교체 UI는 신규 POST replace API 하나를 호출한다. 기존 문구·로그는 보존하고, 동일 원본에 다른 교체 요청은 충돌로 응답한다.
- 날짜 변경은 현재 문구 흐름·VariantA에 적용한다. 레거시 getClientLocalDate 호출 계약과 UTC 운영 지표는 유지한다.
- 운영 조회·LLM·Discord HTTP 경로는 토큰이 필요하다. 공개 문구 API와 이벤트 수집에는 추가 인증을 요구하지 않는다.

## 검증·릴리스

각 버그를 실패하는 테스트로 재현하고 수정한다. DB 롤백·동시성은 D1 로컬 런타임 또는 SQLite 계약 테스트로 검증한다. 정상·실패 API 경로와 자정·DST 경계, 잘못된 토큰·누락된 설정을 포함한다.

릴리스 전 중복 활성 문구를 읽기 전용으로 확인한다. 중복이 있으면 소유자와 처리 방침을 정한 뒤 진행한다. SQL 적용 → Worker 배포 → 프론트엔드 배포 순서이며, ADMIN_API_TOKEN을 Worker Secret으로 등록한다. 이 작업에서는 운영 DB 변경·배포를 실행하지 않는다.


## 회귀 테스트 보완 — 2026-09-11

- **Context:** 구현 검토에서 첫 방문·생성 ID 연결과 자정 경계 검증이 부족했다.
- **Problem:** 기존 테스트만으로 생성 요청 및 D1 이벤트 연결, 자정 직전·직후 운영 집계를 확인하기 어렵다.
- **Goal:** 브라우저 요청의 ID 일치, D1 방문·생성 이벤트 일치, 한국·UTC 자정과 UTC 운영 집계를 검증한다.
- **Non-Goals:** 운영 DB 조회·배포, 서비스 동작 변경, 레거시 정리.
- **Constraints:** ‘요금 테스트’는 앞선 검토의 ‘요구 테스트’ 보완 요청으로 해석한다. 외부 호출을 차단하고 테스트별 DB·시각을 격리한다.
- **선택지:** 실제 브라우저·서버 연결은 통합 범위가 넓지만 환경 의존성이 크다. 브라우저 요청 계약과 로컬 D1 저장 검증을 나누면 빠르고 결정적이므로 후자를 선택한다. 단일 브라우저→D1 E2E를 대체한다고 주장하지 않는다.
- **영향:** 테스트 런타임의 시각을 인스턴스별로 지정하며 기존 기본값은 유지한다. 운영 코드·스키마는 변경하지 않는다.

- **검증 결과:** 프론트엔드 16개, Workers 30개 통과(기존 대비 10개 추가). 프론트엔드 lint와 diff 공백 검사 통과. 기존 punycode deprecation·Browserslist 데이터 경고는 남아 있다. 서비스 버그 수정이 아닌 테스트 보완으로, 이번 실행은 현 구현에 대한 통과 확인이며 과거 실패 재현 순서를 입증하지 않는다.
