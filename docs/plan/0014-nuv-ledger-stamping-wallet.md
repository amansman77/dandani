# Problem 1-Pager: 누브 장부 도장 지갑 준비

## Context

2026-09-28, 누브의 목표가 "나중에 거래소에 상장된 코인으로 사용자 자산이 된다"로
정해졌다. 그 경로로 **내부 원장 + 일일 머클 루트를 체인에 기록(앵커링)** 하고, 코인을
발행하는 날 사용자가 증명을 내고 받아 가는(머클 에어드롭 claim) 방식을 택했다.

- 설계안: https://claude.ai/artifact/BNLbEdsojVkMR4puqiF7oJ
- 배포됨: `e2553b6` 사람당 하루 1누브, `26ab531` 일일 장부 봉인·시간대 고정

## Problem

루트가 우리 DB와 Discord에만 있으면 "장부를 아무도 고치지 않았다"는 보장이 운영자를
믿는 수준에 머문다. 체인에 기록해야 운영자도 지난 장부를 못 바꾼다는 게 증명된다.

체인에 기록하려면 트랜잭션마다 수수료(가스비)를 내야 하고, 그 수수료는 원화나 카드가
아니라 체인의 화폐(Base에서는 ETH)로만 낼 수 있다. 그래서 **ETH가 들어 있고, 워커가
서명할 수 있는 지갑 하나**가 필요하다. 이 지갑이 없어서 체인 기록 단계가 멈춰 있다.

## 지갑이 오기 전까지의 보장 범위

- 누브는 평소처럼 쌓이고 사라지지 않는다. 봉인도 매일 된다.
- 체인 보장은 **지갑이 연결돼 첫 도장이 체인에 올라간 순간부터**다. 도장은 누적을
  새기므로 첫 체인 도장 하나에 그때까지의 모든 누브가 들어간다.
- 지갑 전 기간에 "그 사이 장부가 바뀌지 않았다"는 DB와 Discord 메시지 시각으로만
  뒷받침된다. 밀린 루트를 나중에 체인에 올려도 소급 증명은 안 된다.
- 그래서 그 전까지 외부나 앱에서 "체인에 새겨진다"고 말하지 않는다. 정확한 표현은
  "매일 봉인되는 장부"다. 코인·가격·교환 언급은 지갑과 무관하게 금지다
  (App Store 가이드라인 3.1.5, 투자 권유 문제).

## 준비할 것 (운영자)

1. **새 지갑을 하나 만든다.** MetaMask나 Coinbase Wallet 등. 개인 자산이 든 지갑과
   섞지 않는다. 이 지갑은 도장만 찍는다.
2. **Base 네트워크로 ETH를 약 5달러(약 7천 원) 넣는다.** 업비트·빗썸에서 ETH를 사서
   출금할 때 **네트워크를 반드시 Base로** 고른다. 이더리움 메인넷으로 보내면 수수료가
   비싸고 도장에 쓸 수 없다. 거래소가 Base 출금을 지원하지 않으면 개발 쪽에 알린다.
   - Base 수수료는 건당 보통 1센트 안팎이라 하루 1건이면 5달러로 1년 넘게 쓴다.
     컨트랙트를 처음 배포하는 비용도 여기서 나간다.
3. **개인키를 워커 secret으로 직접 넣는다.**
   ```
   cd workers && npx wrangler secret put ANCHOR_PRIVATE_KEY
   ```
   입력은 화면에 보이지 않고 Cloudflare에만 저장된다. **Discord·채팅·문서·커밋에
   개인키를 절대 붙여 넣지 않는다.**
4. **지갑 주소(0x…, 공개해도 되는 값)만** 개발 쪽에 알려 준다.

## 지갑이 온 뒤 할 것 (개발)

1. `NuvLedgerAnchor` 컨트랙트를 Base에 배포한다. 규칙은 하나 — 한 날짜는 한 번만
   기록할 수 있다(`already anchored`). 소유자는 도장 지갑.
2. `BASE_RPC_URL`, 컨트랙트 주소를 설정한다.
3. 워커에 체인 기록 단계를 붙인다: 봉인 직후 `anchor(day, root, people, totalNuv)`
   호출, 성공하면 `status = 'anchored'` + `tx_hash`, 실패하면 `failed`로 남기고
   Discord 알림, 다음 실행에서 다시 올린다.
4. 밀린 `awaiting_chain` 루트를 날짜 순서대로 체인에 올린다.
5. 잔액이 줄어드는 걸 감시한다 — 도장 지갑 ETH 잔액을 일일 리포트에 한 줄로.
6. 먼저 Base Sepolia(무료 테스트넷)에서 끝까지 돌린 뒤 Base로 옮긴다.

## 보안 메모

- 도장 지갑이 할 수 있는 건 "새 날짜의 루트 기록" 하나뿐이다. 키가 새도 지난 도장은
  못 바꾸고, 잃을 수 있는 돈은 지갑에 든 ETH(약 5달러)뿐이다.
- 키가 샜다고 의심되면: 새 지갑을 만들고 컨트랙트 소유자를 옮기고 secret을 교체한다.
  소유자 이전 기능은 컨트랙트 배포 전에 넣는다.

## 엽서 NFT (2026-09-28 방향 확정)

엽서는 NFT 자산으로 받아 갈 수 있게 한다. 구조는 누브와 같다 — **지금 봉인으로
증명하고, NFT는 사용자가 원할 때 자기 지갑으로 받아 간다(claim).** 우리가 사용자
NFT를 대신 보관하지 않고(커스터디 규제 회피), 원하지 않는 사람은 NFT를 만들지 않는다.

**지금 동작하는 것.** 엽서 만들기는 지금 문장을 한 번에 엽서로 옮긴다(발행번호 붙음).
발행번호가 있는 엽서는 매일 밤 누브와 같은 컷오프로 봉인된다. 엽서 한 줄은

```
[commitment(bytes32), issue_no(uint256), content_hash(bytes32)]
content_hash = keccak256(utf8(JSON.stringify([phrase, practiced_on, logged_days_at_issue])))
```

체인에는 루트만 올라가서 문장은 공개되지 않는다. 번호 없는 옛 엽서는 빠진다.
엽서를 처음 만드는 사람에게도 salt가 생긴다(`ensureNuvAccount`).

**확정된 결정**
1. **문장 공개는 명시적 동의로.** NFT는 공개·영구다. "NFT로 받기"에서 "이 문장이 영원히
   공개됩니다"를 확인받는다. 자동 발행은 하지 않는다.
2. **그림은 IPFS에 고정.** 발행 순간의 엽서 그림과 메타데이터를 IPFS에 올리고, tokenURI가
   그걸 가리킨다. 저장 서비스(Pinata 등) 하나가 필요하다.
3. **배경은 받는 순간 굳는다.** 그 전까지는 지금처럼 바꿀 수 있다.

**지갑이 온 뒤 만들 것**
- `DandaniPostcard` (ERC-721, Base). `claim(to, commitment, issueNo, contentHash, day, proof,
  tokenURI)` — `NuvLedgerAnchor.postcardRootOf(day)`로 증명을 확인하고 발행. 같은
  (commitment, issueNo)는 한 번만.
- "이 엽서가 내 것"은 증명만으로는 부족하다(commitment를 아는 사람은 누구나 낼 수 있음).
  claim 요청에 서버 서명(해당 사용자가 로그인해 요청했음)을 함께 요구한다.
- `NuvLedgerAnchor.anchor`에 `postcardRoot`, `postcards` 인자를 추가한다.
- 앱: 엽서함 카드에 "NFT로 받기" → 동의 → 지갑 연결 → claim. 받은 엽서엔 표시만.

**지키는 선**
- App Store: 자기 NFT를 보여 주는 건 허용, NFT 소유가 기능을 열면 안 됨, 앱에서 발행을
  팔면 인앱결제. 무료 claim + 보여 주기만. "되새기면 NFT" 같은 보상 표현 금지.
- 국내법: 한 장씩 다른 NFT는 보통 가상자산으로 보지 않지만, 대량 발행·분할·결제 수단화하면
  가상자산으로 볼 수 있다(금융위 NFT 가이드라인). 엽서를 사고파는 설계 전엔 검토.

## 아직 열려 있는 것

- **다계정**: 계정은 기기에서 만든 ID라 여러 개를 만들면 그만큼 누브가 쌓인다.
  코인 claim 시점에 본인 확인(예: 휴대폰 인증)으로 막는다. 지금은 막지 않는다.
- **증명 화면**: 헤더 `누브 N`을 누르면 "9월 28일 장부에 새겨졌어요 · 탐색기에서 보기".
  체인 도장이 일주일쯤 안정적으로 찍힌 뒤 붙인다.
- **법률 검토**: 거래 가능한 코인을 발행하기 전에 가상자산이용자보호법·특금법 검토.
