# Problem 1-Pager: 불필요한 도메인 용어 제거

## Context

현재 제품의 표준 한국어는 `문장`이지만 활성 프런트엔드와 운영 리포트에는 같은 개념을
뜻하는 `문구`가 남아 있다. README에는 현재 기능이나 지표에 직접 대응하지 않는 과거의
추상적 가치·훈련 용어도 남아 있다.

## Problem

AI 에이전트가 `문장`, `문구`, `phrase`를 서로 다른 개념으로 해석할 수 있고, 현재 제품을
감정 회복력 측정 또는 감정 훈련 기능이 있는 서비스로 오해할 수 있다.

## Goal

- 사용자 화면, 오류, 운영 메시지, 활성 코드 주석의 한국어를 `문장`으로 통일한다.
- README에서는 현재 동작으로 설명할 수 없는 추상 용어를 제거한다.
- API·DB·분석 계약의 영문 `phrase` 식별자는 유지한다.

## Non-Goals

- `phrase` API, DB 컬럼, 이벤트 이름 변경
- 역사 문서의 당시 용어 수정
- 제품 기능이나 사용자 흐름 변경

## Constraints

- 사용자에게 보이는 행동 의미와 기존 API 호환성을 보존한다.
- 비활성 디자인 변형도 다시 활성화될 가능성을 고려해 같은 용어를 사용한다.

## Options

1. `phrase`까지 `sentence` 등으로 변경: 영문과 한국어가 직역으로 맞지만 API·DB·분석
   마이그레이션 위험이 크다.
2. 한국어 동의어 `문구`만 제거하고 계약 용어 `phrase`를 유지: 변경이 작고 호환성을
   보존한다.

**Decision:** 2번을 선택한다.

## Impact Note

문자열과 주석만 바뀌며 저장 형식과 요청/응답은 동일하다. 사용자는 같은 흐름에서
`문구` 대신 일관된 `문장` 안내를 보게 된다.
